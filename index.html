How an API evaluates a request

An authenticated user changes the account number in the URL to access another user's records. The login is valid, so only the authorization check can stop the request.

GET /accounts/4822/statements

  1. Input validationAccount number is well formedPassed
  2. Rate limitWithin the allowed limitPassed
  3. AuthenticationValid signature, token not expiredPassed
  4. AuthorizationAccount 4822 belongs to another userBlocked
  5. Database queryNot reachedNot run

The same user requests their own account. All checks pass, and the query uses bound parameters so that input cannot alter it.

HabiTrash

Capstone project, 2025 to 2026

A smart waste bin that photographs each item, classifies it with AI, and sorts it into one of four compartments. Sensors track how full each compartment is, and authorized staff monitor the bins from a website and an Android app.

My role
AI developer and backend developer. I built the backend, the security layer, and the database, and contributed to the hardware. Teammates contributed frontend pages.
Stack
React, Node.js, Express, MongoDB Atlas, Socket.IO, Python, FastAPI, PyTorch, Gemini API, TensorFlow Lite, Kotlin, ESP32, Raspberry Pi
Source
Private repository. Walkthrough available on request.

How it works

  1. A student places an item on the tray, and a Raspberry Pi sends a photo to the AI server.
  2. The server runs SigLIP 2 models and asks the Gemini API at the same time.
  3. If both choose the same category, the arm sorts the item. If they disagree, the item is held on the tray until it is removed or rescanned.
  4. ESP32 sensors report how full each compartment is, and the backend sends live updates to staff on the website and app.

Backend and database

  • Built the REST API with Node.js and Express, covering users, bins, scans, collections, notifications, and dashboard data.
  • Designed the MongoDB database, with models for users, bins, sensor readings, scans, collections, notifications, refresh tokens, and audit logs.
  • Sent live bin updates and alerts over Socket.IO, available only to signed-in clients.
  • Implemented a full-bin lock: a compartment that stays full for three minutes locks the bin until it is emptied or unlocked by staff.

Security

  • Built authentication with bcrypt password hashing, JWT access tokens, rotating refresh tokens, and role-based access control.
  • Protected accounts with per-account login lockout, rate limiting, email OTP verification, reCAPTCHA, and input validation.
  • Recorded security events in an audit log and blocked cross-site requests with an origin check.
  • Authenticated device reports with a service key compared in constant time.
  • Covered these protections with automated tests using Mocha and Supertest.

AI and results

  • Combined SigLIP 2 models with the Gemini API, so an item is sorted automatically only when both agree.
  • Added fallbacks: without Gemini, the SigLIP 2 models sort only at 0.60 confidence or higher. Without the AI server, the Raspberry Pi classifies items with its own TensorFlow Lite models.
  • In a test on 18 real bin photos, 16 items were sorted correctly, 0 went to the wrong compartment, and 2 were held for review.
  • The SigLIP 2 models alone reached 80.97% accuracy on 289 unseen images. With agreement required on those images, 63.3% were sorted correctly, 4.5% went to the wrong compartment, and 32.2% were held.
